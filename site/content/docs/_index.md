# r3ply Docs

## Getting Started

To start needing r3ply you will need a `signet` and config. You can generate both of them below. A signet is a cryptographic envelope issued to a specific domain ― your site – on behalf of a r3ply server.

There is a 1:1 relationship between site and r3ply server via the signet. Your signet therefore can not be used with other r3ply servers by other sites, and it is what allows r3ply to provide privacy as well as the ability to moderate comments. **Signets are required**.

**Note: it is very common to use the same config across multiple domains, such as staging changes on a subdomain while you test out a big feature. To do this just generate another signet for each domain, and add it as another site entry to your config.**

### Install r3ply CLI Tool

Then download the r3ply CLI tool to help you validate your config and simulate comments as you make changes to it.

```sh
# install globally
npm install -g @r3ply/cli

# initialize r3ply at the top-level directory of your project
re init
```

You should see output similar output as this:

```sh
Initialized empty r3ply project at /Users/spence/Developer/spenc.es

Add the following site entry to your config:

[[site]]
domain = "site.local.test"
r3ply = "cli.r3ply.test"
signet = "aT57Rm7B_3YGqNbRgaI5gw"
issued = 2025-08-27
```

As you can see, the CLI tool will also provide your site with a signet for simulating comments locally.

### Putting it All Together

After following the steps above we should have a config similar to the following, although your config will have slightly different values to reflect your site's domain.

```toml
# r3ply configuration - see /docs/config for more
version = "0.0.1"

# each site x r3ply combo has an entry
[[site]]
domain = "example.com"
r3ply = "r3ply.com"
signet = "iSQIIBcF7ka2UURJpFDkYw"
issued = 2025-08-26

# generated by running `re init`
[[site]]
domain = "site.local.test"
r3ply = "cli.r3ply.test"
signet = "aT57Rm7B_3YGqNbRgaI5gw"
issued = 2025-08-27

# more moderation options, e.g. `type = "webhook"`, available
[comments.email.moderation]
type = "github"
repo = "https://github.com/you/<YOUR_REPO>"
"file_path_{}" = "content/comments/{{ comment.id[:8] }}.md"
```

We can now run `re config validate` – within your project – to see if this config is valid. If it immediately returns without any output then it means the config is OK.

Before moving to the next section, try changing some part of the config and re-running `re config validate`! You should see something like this:

```json
config failed validation:
[
  {
   "keywordLocation": "#/additionalProperties",
   "instanceLocation": "#/sitesasdmalskmda"
  }
]
```
